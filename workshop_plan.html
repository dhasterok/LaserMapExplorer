What today covers

LaME turns element maps into something you can rapidly explore: import, filter, plot, cluster, calculate, and get mineral formulae out the other end.

We work through the day the way you would work through a real dataset, rather than feature by feature.

Part I — RM01, start to finish. One garnet, taken from the files the instrument software produced all the way to a map of its mineral end-members. Everything else today is a variation on this sequence.

Part II — two more garnets. The same analysis, faster, on samples that differ in ways that matter. This is also where we keep a record of what we did.

Part III — pyrite. A different mineral system, uncalibrated, where you drive.

Part IV — an XRF core scan. A different instrument, a different import route, and a million pixels of semi-quantitative data.

Ask questions whenever you have them. The schedule has slack in it for exactly that, and if there is something you want to know how to do with your own data, we can usually do it on the spot.

LaME is beta software and this handout is honest about that. Where something is unfinished you will see a Not in this build box telling you what you would see and what to do instead. Those boxes are not apologies — they are there so you do not waste the workshop discovering them yourself. A consolidated list is in Known limitations in this build.

One part of the chain is not yet yours to drive: going from raw counts to calibrated concentrations inside LaME. Where we need calibrated data, it was prepared beforehand in iolite, and you will see how it is brought in. The presenter will demonstrate the parts that are not ready rather than asking you to click through them.

The LaME main window immediately after opening. There are four main areas in the window: (1) Control Toolbox, left; (2) plot canvas, center; (3) Styling Toolbox and Plot Tree, right; (4) bottom tabs; (5) the toolbar.

Where to find LaME

LaME is built around five separate GitHub repositories. They can all be found by visiting: GitHub

  • LaserMapExplorer, the main application machinery and GUI components
  • lame-core, core utilities required by LaME and the other repositories
  • siesta-rest-editor, used to produce reSTructured text notes within LaME. Siesta can also be used as a stand-alone application for viewing, editing, and printing documents.
  • blueberry-color-tools is used within LaME to create and modify colormaps and select colors. Like Siesta, Blũberry can be used as a stand-alone application.
  • global-geochemistry, utilities for producing various geochemical plots displayed within LaME and much more. It was originally written to process large geochemical datasets and has some mapping capabilities, geophysical property estimation, and interfaces with tectonic shapefiles and a metamorphic conditions dataset.

The datasets

All real data, from four different instrument setups.

Sample Pixels Material Notes
RM01 95,676 Garnet 476 × 201 px, 6.6 × 16 µm, 3.14 × 3.22 mm. A metamorphic garnet partly dissolved. 28 analytes: full REE suite plus Ca, Fe, Mg, Mn, Al, Ti, Cr, P, Li, Zr, Th, U, Pb. Our primary sample, and the one we import ourselves.
WOS-02 123,256 Garnet 33 analytes. Adds Si, Na, Sr, Ba and a second Pb isotope. The largest of the garnets.
TR1-07 59,917 Garnet 33 analytes, same suite as WOS-02. The smallest and quickest of the three.
71A-Py 12 29,666 Pyrite 91 scan lines × 326 px, 20 × 6.1 µm. 30 analytes: S, Fe and the chalcophile suite — Co, Ni, Cu, Zn, As, Se, Ag, Cd, Sn, Sb, Te, Au, Hg, Tl, Pb, Bi. Gold is below detection in most pixels, so the chalcophile story is in Cu and As.
core 7 ~997,000 Drill core Five scanned segments, 1200 px long by 158–181 px wide, 26 element channels. X-ray fluorescence intensity, not concentration.

What these datasets cannot do — all five limits are properties of the data, not of the software:

  • RM01 has no silicon. Garnet is X3Y2Z3O12, and Si normally fills the tetrahedral Z site. Without it, LaME fills Z with aluminium instead. We use this deliberately in 11. Mineral formulae and the dominant phase — it is the clearest demonstration you will get of what the stoichiometry calculation needs from your data.
  • None of them can do Lu–Hf dating. That needs 176Lu/177Hf and 176Hf/177Hf. These maps have 175Lu and at most one Hf isotope. The capability is real — you will see a result from a different sample — but no amount of clicking will produce an isochron from today's data.
  • The pyrite map is uncalibrated. Values are counts per second, not ppm. Maps, filters, clusters and biplots are all valid on CPS. Mineral formulae and chondrite normalisation are not, so do not run the Stoichiometry dock on it.
  • The XRF core data is intensity, and each channel was scaled separately. Patterns within one element across the core are meaningful; the ratio of one element's number to another's is not. Cluster it, map it, biplot it — but do not read the values as concentrations.
  • Isotope names differ between samples, because the three garnets were run on different setups. RM01 has Fe57, Ti49, Cr53; WOS-02 and TR1-07 have Fe56, Ti47, Cr52. When a step names a field, check the sample you are actually on.

Part I — RM01, from files to formulae

1. Importing RM01

Goal: turn 28 files of numbers into a loaded sample, and understand what LaME needed from you to do it.

The files in data/LA-ICP-MS/RM01/ are matrix exports from iolite: one CSV per analyte, each a bare rectangle of numbers with no header row and no coordinates — RM01 Fe57_ppm matrix.csv and 27 others. Every file is the same shape, and that shape is the map.

What they do not contain is any statement of how big a pixel is. That is what you supply in the import dialog, and it is the one part of importing you have to get right.

Watch, do not click

Calibrating raw counts to ppm is not yet something LaME will do for you. These files were calibrated in iolite first. The presenter will show where that step will live.

  1. Home toolbar page → Import Files. The Map Importer dialog opens.

  2. Set Data type to LA-ICP-MS and Method to quadrupole.

  3. Click Open directory and choose data/LA-ICP-MS/. The metadata table fills with one row per sample it found — RM01 among them.

  4. Fill in these three columns on the RM01 row:

    Column Value Why
    Spot size (µm) 16 The laser spot, and so the spacing between adjacent scan lines. This becomes dX.
    Sweep (s) 0.279 The mass spectrometer's cycle time — how long one pass through all 28 masses took.
    Speed (µm/s) 23.66 How fast the stage moved under the beam. Speed × sweep is how far the spot travelled per reading, and so becomes dY.

  5. Watch the dX and dY columns as you type. They are computed, not editable, and they should settle on dX = 16 and dY = 6.6.

  6. Leave Swap XY, Reverse X and Reverse Y unticked.

  7. Click Select files on the RM01 row to see what LaME thinks it has: 28 rows, one per file, each with the analyte it parsed out of the filename. Check a couple — RM01 Fe57_ppm matrix.csv → Fe57. Close it.

  8. Click Import.

Checkpoint 1

RM01 appears in the sample selector in the pinned toolbar, and a field map is on the canvas. The axes run to roughly 3140 µm in X and 3220 µm in Y, and the map is very nearly square.

Axes in the thousands but the map a thin sliver? dX and dY are the wrong way round — check that Swap XY is unticked.

Axes running 0–476 and 0–201? Spot size, sweep and speed were left blank, so LaME fell back to one unit per pixel. Re-import with the three values above.

The Map Importer dialog with data/LA-ICP-MS/ loaded. Data type on LA-ICP-MS, Method on quadrupole. The RM01 row visible with spot size 16, sweep 0.279, speed 23.66 typed in and the derived dX=16 / dY=6.6 cells showing.

Why this matters

Nothing downstream warns you about wrong pixel dimensions. The map still draws, the clusters still cluster, the formulae still compute. What changes is the scale bar, the aspect ratio, and every distance you measure off the map — so a profile across a garnet rim comes back with the wrong width and nothing tells you.

The arithmetic LaME uses is in the dialog: dX = spot size, and dY = speed × sweep. If you can reconstruct those three numbers for your own data, you can check it.

Save it before you do anything else

  1. Save Project in the pinned toolbar. Put it on your Desktop, under your own name — not inside the workshop folder.

Do this now rather than later, for two reasons that are not obvious.

It arms the autosave. LaME autosaves every ten minutes, but an untitled project has nowhere of its own to go — it is written to a scratch location and stays untitled. Once the project has a name, autosave writes back to it, and the afternoon's work is protected without you thinking about it again.

It creates the project folder. Saving establishes the directory that the rest of the day writes into: your notes file lives there, and figures/ and data/ subdirectories appear beside it the first time you export a plot or a table. Section 14 depends on that folder existing.

Try this: re-import the same directory with Swap XY ticked and compare. It is worth seeing once what a transposed map looks like, so that you recognise it later.

What you just learned. LaME reads a directory of per-analyte matrix files as one sample. The geometry comes from you, not from the files. The derived dX/dY columns are your check that it was understood correctly. Saving the project early is what makes autosave and the project folder real.

2. First look at the maps

Goal: read the sample before analysing it.

  1. Control Toolbox → Field Viewer, plot type field map.
  2. Step the Color field through the analytes. Start with Mn55, Ca43, Fe57, Mg24 — the major garnet cations — then Y89 and a few REE.
  3. In the Styling Toolbox on the right, open Coloring and try a different Colormap, then set Scale to log. Trace elements spanning three orders of magnitude are unreadable on a linear colour ramp.

You should be able to see growth zoning, and the partial dissolution the sample is named for.

Rather than look at individual maps, we can look at all of them rapidly using the Quick View canvas tab. The user is able to create a custom sort of the maps in this view. The default is to arrange the maps by compatibility, often resulting in a gradual visual changes from map to map that reflect processes within a mineral and rapid changes that relate to different minerals.

When you are done examining the maps, select the Single View tab.

Quick View of all analytes collected for the sample. This view is more for reference than analysis, allowing the user to quickly assess the maps and consider a preliminary plan for the data analysis.

Not in this build

The Preprocess page offers gradient map directly below field map. It produces nothing in this build — either a warning about noise reduction, or silence with the previous plot left on screen. Everything today happens on pages whose plot lists contain no unfinished entries.

Try this: the Multi View tab above the canvas holds several plots side by side. Add four element maps to it and compare them at once rather than in sequence.

What you just learned. The Control Toolbox page you are on determines which plot types are offered. Colour scaling is a decision, not a default.

3. Correlations

Goal: find out which elements are telling you the same thing before you choose what to plot.

  1. Still on Field Viewer, set plot type to correlation.
  2. Set Method to Pearson, then compare against Spearman. Pearson assumes a linear relationship; Spearman only assumes a monotonic one, so a large gap between them is itself informative.
  3. Tick C² to show correlation squared — the shared-variance view.

Look for the blocks. The REE should correlate strongly with each other, and Mn, Ca, Fe and Mg should tell a different story — that is the growth-zoning signal separating itself from the REE budget.

The RM01 correlation matrix, Spearmann, with all 28 analytes.

Not in this build

The correlation matrix ignores filters and masks. Later today you will restrict the map; the correlation plot will not respond. The same applies to the ternary map.

To see a filter's effect, use field map, histogram or roi map.

What you just learned. Correlation method choice is a real decision. The matrix is the cheapest way to decide which analytes are worth carrying forward.

4. Choosing analytes and building ratios

Goal: control which analytes are in play, and build ratio fields.

Nothing in LaME plots an analyte you have not selected. That selection also drives what the correlation matrix shows and what clustering and PCA use, so it is the first real control you have.

  1. Click Analytes in the pinned toolbar row. The Select Analytes and Ratios dialog opens on a square grid of your analytes. The background colors are correlation coefficients. The matrix is symmetric across the diagonal, but there is a difference when selecting above or below the diagonal as it inverts the ratio for the same two elements.
  2. The diagonal cells are the analytes themselves. Click along it to select Mn55, Y89, Sm147, Eu153, Gd157, Ca43, Fe57, Mg24. Selected cells highlight.
  3. The off-diagonal cells are ratios. Above the diagonal gives row ÷ column; below gives column ÷ row. Find the cell where Y89 meets Mn55 and click it once.
  4. Add a second ratio that means something petrologically — Mg24 over Fe57 is the garnet one to have.
  5. Your choices appear in the Selected list on the right, with columns Field, Scaling and Normalized. The ratios appear as Y89 / Mn55 and Mg24 / Fe57.
  6. Click Done.

The background colours in that grid are the correlation matrix from section 3 — so the dialog is already telling you which analytes co-vary while you pick them.

The Select Analytes and Ratios dialog, mid-selection. Several diagonal cells highlighted, and one off-diagonal cell highlighted in yellow.

Now put the ratios on the map:

  1. Field Viewer, plot type field map.
  2. Set the colour field type to Ratio and the field to Mg24 / Fe57.

A ratio map often shows a boundary that neither element shows on its own, because it divides out whatever varied in both.

Checkpoint 2

The Plot Tree on the right has a Ratio branch with two entries, and a ratio map is on the canvas.

  1. Save Project again. It overwrites the save you made in section 1 — no dialog, no new file.

From here on, start each section by saving. You are building your own recovery points, and they are the first thing to reach for if your screen stops matching everyone else's.

What you just learned. Field selection gates everything downstream. Ratios come from the analyte grid, and they are fields in their own right — mappable, filterable, clusterable.

5. A calculated field: Eu*

Goal: build a field that is not in your data.

Europium anomalies need the interpolated Eu you would expect from the neighbouring REE. That is what the Calculator is for, and it is the general tool for any field you can write as an expression.

First, the reference — do this before calculating anything normalised:

  1. In the Control Toolbox, find the Ref. row and set it to a chondrite — CI chondrite [AG89].

Normalised fields divide by this reference, and the default is bulk silicate Earth, which is not what you want for a REE anomaly.

  1. Analysis toolbar page → Calculator.

  2. In the saved-formula box, choose Eu*. The formula appears:

    {Analyte.Eu153_N}/({Analyte.Sm147_N}*{Analyte.Gd157_N})^(1/2)

    Fields are written {FieldType.Field}. The _N suffix means reference-normalised — which is why the reference had to be set first.

  3. Click Calculate.

  4. Plot it: Field Viewer, plot type field map, colour field type Calculated, field Eu*.

  5. In the Styling Toolbox, select the Colors tab. Change the C limits to 0.05#. and 0.3.

Your canvas shows a smooth, low-contrast Eu* map — much flatter than a raw element map, because you have divided out the overall REE level and are left with just the anomaly.

Not in this build

The Calculator's keypad offers case() and otw() buttons for conditional expressions. Conditionals do not work in this build — you will get "could not evaluate conditional statement".

The shipped Calculator documentation also describes a case(...) function. That syntax has never existed in any version. Ignore the ``case()`` section of the Calculator docs. Arithmetic, logs, powers and roots all work fine.

Canvas showing the Eu* field map on RM01. Three things have been done to separate docks on the right to display this map.

Try this: write your own. {Analyte.Y89}/{Analyte.Ho165} is a useful one — Y and Ho have nearly the same ionic radius, so their ratio is sensitive to processes that fractionate by something other than size.

What you just learned. Anything you can write as an expression over existing fields becomes a field. Normalised fields depend on the reference being set first.

6. Biplot: Fe, Mn

Goal: get three elements onto one plot, and then back onto the map.

  1. Control Toolbox → Scatter and Heatmaps. The axis rows now have labels X, Y, Z and Color.
  2. Plot type scatter. Set X = Fe57, Y = Mn55, leave Z empty, and set Color = Ca43. That is your biplot; a third variable as colour is usually more informative than a third axis.

Biplot of the entire map, Fe vs. Mn with Ca concentration used to color the pixels. The result can be used to clearly identify the garnet as the generally higher Ca points.

Try this: double-click any leaf in the Plot Tree. It restores that plot — type, fields and styling together. The tree is a record of your session, not just a list.

What you just learned. Scatter and heatmap answer the same question at different densities. Adding Z turns either into a ternary. The ternary map is how a three-element relationship gets back onto the spatial map.

7. REE patterns: the TEC plot

Goal: look at all the rare earths at once, in the way petrologists expect to see them.

A trace-element compatibility diagram — a spider plot — puts the REE in order of ionic radius and normalises each to a reference. The shape is the information.

  1. Control Toolbox → n-Dimensional. Plot type TEC.
  2. Set the analyte set to REE. LaME ships preset element lists; REE is the one you want here.
  3. Check the Ref. row still reads CI chondrite [AG89]. The TEC plot is normalised, so the reference is doing real work.
  4. Set Color to a field — start with Mn55.

Because every one of your 95,676 pixels is a sample, this is not the handful of lines you would get from spot analyses. What you are looking at is the envelope of REE patterns across the whole map, and the Eu anomaly you calculated in section 5 should now be visible as a notch in the middle of it.

  1. Plot type radar, same analyte set. The same data on polar axes. Which of the two reads better depends on how many groups you are comparing — radar is usually clearer for three or four, TEC for more.

The TEC plot of RM01 with the REE preset, chondrite-normalised. The Eu notch is visible.

We come back to this plot in section 10, once there are clusters to colour it by — which is when it becomes a comparison rather than a description.

What you just learned. The n-Dimensional page takes an element list, not axes. Preset lists save you rebuilding common suites. Normalisation is live, so the reference setting matters here as much as in the Calculator.

8. Principal components

Goal: find out how many independent things the data is actually doing.

You have 28 analytes, and section 3 showed that many of them are telling you the same story. PCA rewrites the data in terms of what varies, in order.

  1. Control Toolbox → Dimensional Reduction. Opening the page runs PCA immediately with the current field selection.

  2. Set Method to PCA: Principal component analysis.

  3. Plot type variance. This is a scree plot: how much of the total variance each component carries. Usually three or four components carry nearly everything.

    Note the number where the curve flattens. You need it twice more today.

  4. Plot type basis vectors. This shows what each component is made of — which analytes load onto it. A component dominated by the REE and one dominated by Mn–Ca–Fe is the same split section 3 showed you, now quantified.

  5. Plot type dimension scatter. PC1 against PC2, every pixel. Set Color to Mn55 and look for structure — separate clouds here mean separable populations.

  6. Plot type dimension score map. Each component mapped back onto the sample. PC1 usually looks like the dominant zoning; the higher components are where the interesting and less obvious patterns live.

Principal component analysis scree plot.

Basis vectors resulting from principal component analysis. Larger positive and negative values have greater influence on the principal component score.

Principal component 1.

Principal component 2.

Why this matters

The score maps are worth dwelling on. A principal component is defined without any reference to position — PCA does not know these numbers came from a map. When a score map comes out looking like coherent growth zoning anyway, that is the data telling you the chemical variation and the spatial structure are the same phenomenon.

What you just learned. The variance plot tells you how many components to keep; the basis vectors tell you what they mean; the score maps tell you where they are. You need all three to use PCA honestly.

9. Clustering

Goal: let the data propose its own zones, then test whether they are real.

  1. Control Toolbox → Clustering. Opening the page runs clustering immediately with the current settings and plots the result, so you will see groups before you have chosen anything.

k-means

  1. Set Method to k-means and No. clusters to 5.
  2. Plot type cluster map.
  3. Click Randomize beside the Seed box and watch the map. k-means starts from random centres; if your zones survive several seeds they are robust, and if they reshuffle they were not there.
  4. Plot type cluster performance. This sweeps the cluster count and scores each one, which is the closest thing to an objective answer to "how many clusters?". Set No. clusters to whatever it suggests, then go back to cluster map.

fuzzy c-means

k-means assigns every pixel to exactly one cluster. Fuzzy c-means gives each pixel a membership in every cluster, which is a better model of a boundary that is genuinely gradational — like a diffusion profile, or a growth zone grading into the next.

  1. Set Method to fuzzy c-means. Same cluster count.
  2. The Exponent box controls how fuzzy the result is. 1.0 would reproduce k-means; higher values blur the memberships. 2.0 is the conventional starting point.
  3. Plot type cluster score map. This is the one to look at — it maps the membership in a single cluster as a continuous field, so you can see the boundary width rather than just its position.
  4. Increase the number of clusters to 6 and 7 and compare the results with the initial 5 clusters.

Compare it against the k-means map. Where the two agree, you have a real boundary. Where fuzzy c-means smears something that k-means drew as a sharp line, the line was an artefact of being forced to choose.

Clustering on principal components

Much of what the clustering sees is the same signal repeated across correlated analytes. Reducing first often gives cleaner groups.

  1. Go back to Dimensional Reduction once, so the PCA scores exist.
  2. Return to Clustering. Tick the PCA checkbox and set No. basis to the number you took from the variance plot in section 8.
  3. Re-cluster, with the same method and cluster count as before.

Important

Run PCA before ticking that box. If no PCA scores exist, LaME falls back to the raw analytes without telling you, and the comparison you were trying to make silently does not happen.

Compare against the raw-analyte clustering. The large boundaries usually survive; what moves is the internal subdivision, because PCA has reweighted what counts as similar.

Clustered result using fuzzy c-means clustering for 6 clusters with an exponent of 2.1 using 7 PCA basis vectors as preconditioning. The result highlights three regions within the garnet. This may be too many but it separates a core (Clusters, 5 and 6) from a rim (Cluster 1) of the garnet and identifies three additional phases.

Now select plot type score map and examine how well each pixel corresponds to each cluster. This score can be used for filtering the data in addition to clustering to restrict the data to the best results for additional analysis. Why this matters

PCA before clustering is often presented as a tidying step. It is not neutral — it decides which variation the clustering is allowed to see. Running it both ways on the same sample is the honest way to find out whether a result depends on that choice, and it takes two minutes.

Not in this build

The Distance combobox on this page has no effect — the distance-metric code is not active in this build. Changing it recomputes and gives an identical result.

Also: HDBSCAN works as a method, but combining it with cluster performance silently does nothing. HDBSCAN discovers its own cluster count, so there is no k to sweep. Use cluster performance with k-means or fuzzy c-means only.

Changing what clustering sees

Clustering uses exactly the fields you selected in section 4.

  1. Click Analytes and add two or three light REE — La139, Ce140, Nd146.
  2. Click Done. Because you are on the Clustering page, it recomputes and replots automatically.

Adding light REE will usually sharpen a growth-zoning boundary, because those elements partition strongly during garnet growth.

Note

That automatic recompute only happens while you are on the Clustering or Dimensional Reduction page. From anywhere else, change the selection and then press Update Plot.

What you just learned. Clustering reads your field selection, so curating it is the main lever you have. k-means draws hard boundaries; fuzzy c-means tells you how hard they really are. PCA first changes the answer, which is why you run it both ways.

10. Filtering by cluster, and replotting

Goal: use the clusters as a selection tool, then look at everything again through it.

A cluster map is a picture. The Clusters tab turns it into a filter.

Naming and masking

  1. Masking Toolbox at the bottom → Clusters tab. The table lists your clusters with Name, Link, Color, % Total and % Filtered.
  2. Rename them in place — core, mantle, rim, matrix. These names follow through into every legend, the Notes report and the stoichiometry scope list, so it is worth doing now rather than later.
  3. Recolour one by clicking its Color cell.
  4. If two clusters are clearly the same zone, tick both and click Link Clusters — they then behave as one class.
  5. Tick the clusters that are garnet and press Create Cluster Mask.

Everything outside those clusters is now masked, and every plot that follows uses garnet pixels only. No bounds to choose, because the clustering already found the boundary.

  1. Tick one cluster and click Create Region instead. It becomes an ROI — which is what the stoichiometry calculation in section 11 needs to scope itself to.

Replotting through the clusters

Now go back and redo two plots with the clusters as the colour field. This is where the day's work starts compounding.

  1. Scatter and Heatmaps, plot type scatter, X = Fe57, Y = Mn55, Z = Mg24 — your ternary from section 6 — and set Color field type to Cluster.

  2. From the Cluster Table, select cluster 1. This should be the garnet.

  3. Now let's look at a ternary system, plot type scatter, X = Dy163, Y = Er165, Z = Lu175 and set Color to Mn55

    The ternary is now a map of which zone sits where in composition space. If your clusters are real, they occupy distinct regions of the triangle. If they overlap completely, the clustering found something the ternary does not resolve.

  4. Change the plot type to heatmap, same X, Y, and Z. With 95,000 points, overplotting hides the structure and binning reveals it. In the Biplot and Ternary group, try the Heatmaps statistic — counts, then median.

  5. Now change the plot type to ternary map, same three fields.

  6. In the Ternary Map group, either pick a Colormap or set the four colour swatches — one per vertex plus one for the centre.

  7. Click Ternary map.

Each pixel is now coloured by where it sits in the ternary. This is the single most useful plot in LaME for seeing compositional zoning, because it puts three elements on one map without you choosing which matters most.

Trace element compatibility diagram with REE data for each cluster. The garnet core is clusters 5 and 6 and the rim is cluster 1.

  1. n-Dimensional, plot type TEC, analyte set REE, Color field type Cluster.

    One REE pattern per cluster, chondrite-normalised, on one plot. This is the figure a paper would carry — and it took you three clicks because the clusters already exist. Look at whether the Eu anomaly differs between core and rim.

    Trace element compatibility diagram with REE data for each cluster. The garnet core is clusters 5 and 6 and the rim is cluster 1.

Checkpoint 4

A cluster map with named, recoloured clusters; a cluster mask restricting the map to the garnet; and both the ternary and the TEC plot coloured by cluster with a legend showing your names.

What you just learned. Clusters are a masking and grouping tool, not just a picture. Naming them early pays off everywhere downstream. Any plot gains a grouped version for free once clusters exist.

11. Mineral formulae and the dominant phase

Goal: get apfu, site occupancies and end-member proportions, and map them.

LaME can convert composition into a mineral formula — site by site, with iron split between Fe²⁺ and Fe³⁺ by charge balance. The chemistry behind this is the most heavily validated part of LaME, cross-checked against published mineral-recalculation workbooks for garnet, feldspar, olivine and pyroxene.

Important

Scope it to one region before you touch anything else. The calculation runs pixel by pixel. Across a whole 95,000-pixel map that is minutes of frozen window, several times over. Scoped to one cluster it is seconds.

  1. Analysis toolbar page → Stoichiometry. The Stoichiometric Calculator opens.
  2. First, in the Compute scope group: set Filter to the ROI you made from a cluster in section 10, and tick only that region in the list below. New regions start unticked deliberately — leave the others alone.
  3. Now the Settings group: Mineral = Garnet, Input basis = ppm, Redox method = droop_1987, BDL treatment = zero.
  4. Leave Compare all redox methods switched off. It triples the work.
  5. Click Run.#.

Stoichiometry calculations for the k-means, cluster 1 (all of the garnet). The results show a dominant pyrope composition for this garnet with lesser andradite and spessartine components. Approximately Alm0-Pyr73-Sps10-Adr15-Grs1-Uv1.

New fields appear under field type Stoichiometry:

Field Meaning
Grt_Z, Grt_Y, Grt_X Cations per formula unit on each site — tetrahedral, octahedral, dodecahedral
Grt_pyrope … Grt_uvarovite End-member proportions: pyrope, almandine, spessartine, grossular, andradite, uvarovite
Grt_dominant Which end member dominates at each pixel — a categorical field
  1. Plot it: field map, colour field type Stoichiometry, field Grt_dominant. It draws with a labelled swatch legend rather than a colour bar, because the values are categories rather than amounts.

Dominant garnet phase calculated using the stoichiometry calculator.

What happens without silicon

Now look at Grt_Z. It should be close to 3.0, filled by silicon. On RM01 it is not — RM01 has no Si, so LaME has filled the tetrahedral site with aluminium instead, following the fallback order in the garnet configuration. The end-member percentages that come out are correspondingly wrong.

This is worth seeing rather than being told. The stoichiometry calculation is only as good as the elements you measured, and a missing major element does not produce an error — it produces a plausible-looking answer that is incorrect. We fix this in section 13 by moving to a sample that has Si.

Not in this build

If the Mineral dropdown is empty and outlined in red, the application cannot find its mineral configuration files. Tell the presenter — there is a workaround.

Checkpoint 5

The Plot Tree has a Stoichiometry branch, and a Grt_dominant map with a swatch legend is on the canvas. Grt_Z is visibly not 3.0.

Try this: the Region summary table at the bottom of the dock gives per-region statistics. Switch Region source between ROI and a cluster column to compare formulae between the zones you named in section 10.

What you just learned. Scope first, always. Site totals are your sanity check on whether the calculation had the elements it needed. Grt_dominant maps mineral classification back onto the sample.

Part II — Two more garnets

13. The other two garnets

Goal: repeat the core of Part I quickly on two samples that differ in ways that matter, and get the stoichiometry right this time.

We are not redoing all twelve sections. Four steps, on each of TR1-07 and WOS-02, with the big one being the one RM01 could not do.

  1. Switch sample using the selector in the pinned toolbar: choose TR1-07.

    TR1-07 and WOS-02 are already converted, so they load from .lame.csv directly — no import step. They also have different isotope names: Fe56, Ti47, Cr52 rather than RM01's Fe57, Ti49, Cr53. Your field selection does not carry across, so re-select on each sample.

  2. Cluster it. Clustering page, k-means, 3 or 4 clusters. Pick a field selection first — the major cations plus two or three REE is enough.

  3. Filter to the garnet. Clusters tab → name the clusters → tick the garnet ones → Create Cluster Mask. Then tick one and Create Region for the next step.

  4. Run the stoichiometry, scoped to that region, exactly as in section 11.

    Now compare Grt_Z with what RM01 gave you. With ``Si29`` present it should sit near 3.0, and the end-member proportions are meaningful for the first time today.

  5. Map the dominant phase — field map, field type Stoichiometry, field Grt_dominant.

  6. Make a ternary map, two ways:

    • on the chemistry — Fe56, Mn55, Mg24, as in section 6;
    • on the stoichiometry — put three end-member proportions on the axes instead, Grt_almandine, Grt_spessartine, Grt_pyrope.

    The second is the more interpretable plot: the axes are now mineralogical quantities rather than raw element levels, so a position on the triangle is a composition you could quote in a paper.

  7. Repeat on WOS-02 if time allows. It is the largest of the three, so keep the region small.

Checkpoint 6

At least two garnets have Grt_* fields. Grt_Z is near 3.0 for TR1-07 and clearly not for RM01. You have a ternary map built on end-member proportions.

What you just learned. The whole sequence transfers to a new sample in a few minutes once you know it. Field names do not transfer. Stoichiometric outputs are first-class fields — mappable, plottable, filterable.

Part III — Pyrite

15. Pyrite — your turn

Goal: apply what you have done to a different mineral system, with less guidance, and see what preconditioning does to a clustering.

This section has fewer numbered steps on purpose. You have the tools now; the questions are new.

The questions. 71A-Py 12 is a pyrite-bearing sample. Two things to find out. Does clustering change when you precondition the data with PCA first? And once you have the pyrite on its own, is it chemically uniform, or are there distinct populations within it?

Remember this map is uncalibrated: counts per second, not ppm. Relative patterns are fine; absolute values and mineral formulae are not.

  1. Add data/LA-ICP-MS/71A-Py 12.lame.csv using Open on the Home toolbar page, or simply drag the file onto the window.

  2. Find the pyrite. Field maps of Fe57 and S34. Pyrite is FeS₂, so it should stand out sharply against the silicate matrix in both. Something like 40% of this map is sulfide, so it is not a small target.

  3. Cluster the whole map, on the analytes. Clustering page, k-means, 4 clusters. Choose a sensible set of analytes first (Fe57, S34, Cu65, Co59, Ni60, As75 is a good start). Look at the cluster map: two of the four groups should land on the sulfide and two on everything else.

    Note which clusters are the pyrite, and roughly what fraction of the map they cover.

  4. Now precondition with PCA and cluster again. Visit the Dimensional Reduction page first so the scores exist, then return to Clustering, tick PCA and set No. basis to 3. Re-cluster.

    Compare the two cluster maps. The sulfide/matrix split survives — that boundary is not in doubt — but the way the pyrite is divided within itself changes, and so do the cluster proportions. Neither answer is the "right" one: PCA has reweighted what counts as similar, by dropping the directions in which the data varies least.

  5. Filter to the pyrite with the Cluster tool. Masking Toolbox → Clusters tab. Tick the clusters that are the pyrite, then press Create Cluster Mask.

    Everything outside those clusters is now masked, so every plot that follows uses pyrite pixels only.

  6. Fe against Cu. Scatter and Heatmaps page, plot type scatter: X = Fe57, Y = Cu65, Color = your cluster field.

    Fe is the pyrite's own framework and barely varies; Cu does not substitute into pyrite in any quantity, so where it appears it is telling you about something else — an inclusion, a later overprint, or a different generation of growth. Watch for the points that climb away from the main Fe population.

  7. A histogram per cluster. Field Viewer page, plot type histogram, X = Co59, with Show KDE on and log-scaling set. Then step through your clusters and compare.

    Expect a dramatic separation between the sulfide clusters and the matrix — Co runs a few hundred thousand counts inside the pyrite against a few thousand outside. What you will probably not see is much difference between the two pyrite clusters themselves: Co (and Ni, which behaves the same way) is substituting for Fe fairly uniformly through the sulfide.

    That is a real result, not a failed exercise. It says the populations your clustering found are not Co–Ni populations. Go back to the biplot: Cu65 and As75 are where those two groups actually differ.

Checkpoint 8

Two cluster maps of the same sample (with and without PCA), a cluster mask restricting the map to the sulfide, an Fe–Cu biplot coloured by cluster, and a Co histogram you have compared across clusters.

What you just learned. Clustering is a choice, not a measurement: preconditioning changes the answer, and the way to know how much is to run it both ways. And a huge contrast in one element between two materials tells you nothing about structure inside either of them.

Part IV — An XRF core scan

16. Importing the core 7 scan

Goal: import from a completely different instrument, and understand what you have.

data/XRF/core 7/ holds a scanned drill core, cut into five segments. Each of row1/ … row5/ contains 26 PNG images, one per element — Fe.png, Ca.png, Rh.png and so on. The scanner's software exports element maps as pictures, and LaME reads the pixel brightness as a relative intensity.

  1. Home toolbar page → Import Files.
  2. Set Data type to XRF and Method to image.
  3. Click Open directory and choose data/XRF/core 7/. Five rows appear in the metadata table — row1 through row5.
  4. Set Spot size (µm) to the scanner's pixel pitch if you know it. If you do not, leave it at 1: dX and dY both become 1 and the map axes read in pixels instead of microns. Everything except absolute distance works the same way.
  5. Import row1 to start with. It is 1200 × 181 px — about 217,000 pixels, more than twice RM01.

Checkpoint 9

row1 is in the sample selector and a field map draws as a long thin strip. 26 fields are available, named by element symbol alone — Fe, Ca, Si — with no isotope numbers, because XRF measures elements, not isotopes.

Why this matters

Two things about this data that the numbers will not tell you.

It is intensity, not concentration. There is no calibration behind these values, so Fe = 55 does not mean 55 of anything.

Each element image was scaled independently by the scanner software before it was written to a PNG, and then clipped to the 0–255 range of an 8-bit image. So comparing Fe to Ca pixel-for-pixel is meaningless, and the brightest pixels in any channel may be saturated. Comparing Fe here to Fe there is fine, and that is what makes maps, clusters and zoning valid on this data.

Not in this build

Only LA-ICP-MS and XRF → image import in this build. The other data types populate the metadata table and then stop with a "Not implemented" message, so the table filling in is not a sign that it will work.

What you just learned. The import dialog adapts to the data type. Images are a legitimate data source. What you cannot do with the result is a property of how it was produced, not of LaME.

17. Exploring the core

Goal: find the chemical zones in a core without any concentrations at all.

  1. Look at it. Field maps of Fe, Ca, S, K, Si. Open core7_Video Mosaic.png alongside — the optical image of the core — and compare. You should be able to match chemical boundaries to things you can see.

  2. Find the channels worth using. Plot type histogram and step through the elements. Several are almost entirely zero — Mg, Na, Cu and Ni are above 90% zeros in this core — and they will only add noise to a clustering.

    Why this matters

    Look at the mean intensities and you will find Re and Rh are the two brightest channels in the scan — brighter than Fe, in a rock. That is not rhenium.

    Rh, Pd and Pt are common X-ray tube anode materials, and what those channels mostly record is the tube's own characteristic radiation scattered off the sample. Check what your instrument's tube is made of before you interpret any of them as sample chemistry. Leave them out of the clustering.

  3. Correlations. Plot type correlation, Spearman. With independently-scaled channels, the rank-based method is the more defensible of the two here.

  4. Biplots. Scatter and Heatmaps, heatmap rather than scatter — at 217,000 points the scatter is a solid block. Ca against Fe is a good first pair.

  5. Radar. n-Dimensional page, plot type radar. Build an element list from the channels that carry real signal. This is the plot that will compare your zones once you have them.

  6. Cluster it to find the zones. Clustering page, k-means, start with 4 clusters and use cluster performance to check. Use only the channels you kept.

    The clusters are lithological and alteration zones down the core. This is the result that matters: you have mapped chemical domains in a core with no calibration, no standards, and no concentrations.

  7. Name them and compare them. Clusters tab → name the clusters → then back to the radar plot with Color field type Cluster. One pattern per zone.

Refining by hand

Clustering finds domains by composition. Sometimes you want a region because of where it is — a single band, or everything outside a crack.

  1. Processing toolbar page → Filters. In the ROI table click Add ROI, name it, and leave the row selected. Then in Filter Settings set a field and a range and click Add filter.

    Filters live inside regions of interest: an ROI is a named definition, a filter is one rule inside it. Select the ROI row first. If you add a filter with no ROI selected, LaME quietly creates one — convenient once, confusing the second time.

  2. Plot type roi map on the Field Viewer page. Excluded pixels draw grey. This is the plot to use whenever you want to check what a filter actually did.

  3. Polygons tab. Flip the toggle switch at the left of its toolbar to enter polygon mode, click Create a new polygon, then click round a feature on the core.

    The In/out column controls whether the polygon keeps or removes what is inside it. Use Move a control point, Add a vertex and Remove a vertex to adjust.

  4. Crop on the toolbar restricts the map to a rectangle. Click it, drag a box over the map, adjust the handles, then double-click inside the box to apply — or press Enter, which works once you have clicked on the canvas. Full Map, beside it on the toolbar, puts the whole sample back.

    Crop is only enabled while a map is on screen; it greys out on a histogram or a biplot, because there is nothing spatial to cut.

    Cropping a long core strip down to the interval you care about makes everything downstream faster, and the clustering no longer has to account for pixels you were never going to use.

Not in this build

Polygons are deliberately excluded from clustering. Drawing a polygon around a band and re-clustering will not restrict the clustering to it. To scope an analysis, use an ROI, a cluster mask, or a crop.

Save filter is also unavailable in the packaged build — it tries to write inside the application bundle. Your filters are saved in your project, which is what matters.

Checkpoint 10

A cluster map of row1 with named zones, a radar plot comparing them, and at least one ROI or polygon you drew yourself.

Try this: import row2 as well and cluster it with the same settings. Do the zone boundaries continue across the gap between segments? That is a real question about the core, and you can answer it in about five minutes.

What you just learned. The whole toolkit works on uncalibrated intensity data. Knowing which channels are instrument artefacts is part of the analysis. ROIs, polygons, cluster masks and crop are four different ways to restrict a map, and they are not interchangeable.

  2. Close the project — File → Close Project.

Appendix A: Profiles

Profiles extract a transect across a map — the standard way to show garnet zoning as a function of radius. It works, but the route to it is not the obvious one.

Not in this build

Do not select profile from the plot-type list. It produces a blank canvas. Profiles are driven entirely from the Profiles dock.

  1. Get a field map on screen.
  2. Analysis toolbar page → Profiles.
  3. Flip the toggle switch at the left of the dock's toolbar. Plot type collapses to field map while profiling is active.
  4. Click Create new profile and set control points, then click along the map — for a garnet, rim through core to the far rim.
  5. Set Point radius (how much to average around each point), Interp. distance (spacing along the transect) and Point type (median + IQR is the robust choice).
  6. In Axis Options, set No. subplots, then for each subplot pick a field and click the add button. Several elements stacked against distance is how zoning is normally presented.
  7. Use Edit mode to click out any point sitting on a crack or inclusion.
  8. Save with the export button. Profiles are stored per sample in your project.

Appendix B: reStructuredText in one page

LaME's notes are reStructuredText — plain text that typesets. This is everything you need for a set of workshop notes. Blank lines matter: they separate blocks, and most mistakes are a missing one.

Headings. Underline with punctuation, at least as long as the text. The character you use first becomes level 1, the next new character level 2, and so on — so be consistent.

Sample RM01
===========

Clustering
----------

Emphasis and code.

*italic*, **bold**, and ``literal text`` for field names like ``Mn55``.

Lists. Blank line before and after. Indent continuation lines to line up.

* four clusters, k-means
* PCA with three components
* cluster 2 is the garnet rim

#. auto-numbered
#. second item

Field lists, for metadata at the top of a document:

:Sample: RM01
:Date: 2026-11-14
:Analyst: your name

Figures. The path is relative to the notes file. Everything indented under the directive belongs to it, and the last indented paragraph is the caption.

.. figure:: figures/cluster_map.png
   :width: 80%
   :align: center

   k-means clustering of RM01 on four components.

Tables. The simple form needs only = rules and aligned columns:

======  =========  =======
Zone    Grt_Z      Dominant
======  =========  =======
core    2.98       almandine
rim     2.95       spessartine
======  =========  =======

Admonitions, for anything you want to stand out:

.. note::

   Fe57 is noisy below 100 ppm in this sample.

.. warning::

   Grt_Z is wrong here -- no Si in the data.

Comments — a line starting .. with nothing the parser recognises is ignored:

.. check this against the spot data before using it

That is enough to write notes anyone can read, including you in six months. The full specification is at docutils.org, and the reST Editor toolbar will insert most of these for you.

Appendix C: Getting your own data in

Sections 1 and 16 covered the two routes we use today. The Import tool handles several more.

  1. Home toolbar page → Import Files.
  2. Choose a Data type and Method — LA-ICP-MS with quadrupole, TOF or SF, or XRF with image.
  3. Point it at your directory. The metadata table fills with one row per sample.
  4. Fill in the geometry. For quadrupole and SF, that is spot size, sweep time and stage speed, and LaME derives dX and dY from them — dX = spot size, dY = speed × sweep. For TOF, you give the raster's physical length and width instead, and the per-pixel spacing is derived from the file's own grid.
  5. Use the per-sample Select files button to check which files map to which analytes, and to exclude standards from a line-scan directory.
  6. Import.

Three layouts are recognised, and LaME works out which it is looking at:

Layout What it looks like
Matrix per analyte One file per analyte, each a bare rectangle of numbers. Section 1's RM01, and XMapTools exports.
Line scans One file per laser traverse, all analytes in columns, with a time column. Agilent "Intensity Vs Time" exports. LaME reads the line number out of the filename, sorts the lines, and drops the Printed: footer.
Images One image per element. Section 16's XRF core scan.

If a conversion gives you trouble, send the presenter a raw export and you will get a .lame.csv back.
